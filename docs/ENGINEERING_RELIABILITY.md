# 工程可靠性

## 安全模型

| 等级 | 含义 | 默认行为 |
|---|---|---|
| ReadOnly | 读取项目或数据状态 | 直接执行 |
| Increment | 创建新输出，不替换源数据 | 执行并验证 |
| Modify | 修改现有数据 | 评估影响范围，并按策略请求审批 |
| Destructive | 删除或不可逆地替换数据 | 先备份，再获得明确审批 |

风险分类同时依据经过审查的风险目录与最终调用参数。Domain Pack 可以提高风险等级，但不能降低风险等级。

## 审批完整性

一张 Approval Ticket 记录：

- 规范化工具身份与调用签名；
- 批次中被精确覆盖的调用；
- 语义目标与影响证据；
- 所需权限等级；
- 项目/数据修订指纹；
- 破坏性操作所需的备份证据。

调用内容或所覆盖的宿主状态一旦变化，票据立即失效。审批是针对某项具体操作授予的能力，而不是临时“管理员模式”。

## 验证与证明

验证发生在执行之后，并直接读取宿主状态。当前策略包括输出存在性、最小数量、字段存在与赋值情况、空间参考以及拓扑检查。

v3 在此基础上增加证明义务。例如，一个已经填充值的面积字段，并不能证明它采用了测地线面积、平方米单位与两位小数。参数级证明会在相同合同约束下重新计算有限样本，并且只闭合完全匹配的 Proof ID。

由于 ArcGIS 字段计算器与 SDK 路径无法保证位级一致，测地线面积采用有界的跨 API 容差；长度和平面面积继续使用严格舍入容差。Ledger 同时记录观测误差与允许的最大误差。

## 诚实的完成判定

`GoalCompletionReport` 对以下内容进行对账：

- 预期目标与已满足目标；
- 必要证明与已满足证明；
- 尚未解析或仍有歧义的资源；
- 失败、阻塞与跳过的业务步骤；
- 不应抬高业务完成度的辅助探查。

模型生成的文本可以补充澄清问题，但不能将 Partial 或 Failed 提升为 Completed。

## 可观测性

四类互补记录分别回答不同问题：

1. **Transcript**——用户、模型与工具之间交换了什么；
2. **Verification Ledger**——检查了什么，以及为何通过或失败；
3. **Context Snapshot**——Agent 当时观察到了什么项目状态；
4. **Audit Log**——哪些敏感操作被允许、阻止或审批。

Run ID 与 Span ID 将模型延迟、工具执行、结果验证和最终输出关联起来。路径与项目本地标识在写入 Transcript 前会被脱敏。

## 持久化与恢复

Checkpoint 保存活动计划、消息、观察、验证、目标范围与执行账本。Session Lease 提供独立于内存关闭回调的持久事实。

正常终态写入顺序为：

```text
终态 Checkpoint
  → 终态项目记忆摘要
  → session_end
  → 释放 Lease
```

如果 ArcGIS Pro 未触发回调就直接退出，下一个进程可以接管过期 Lease，并记录 Interrupted 终态。恢复流程不会伪造正常完成结果。

## 测试策略

当前快照包含 521 个自动化测试，覆盖：

- 纯安全策略与规划策略；
- 调度器审批与备份行为；
- 目标覆盖与证明闭包；
- Checkpoint 迁移与 Session Lease；
- Transcript 脱敏与事件顺序；
- manifest 默认值的可移植性约束；
- MCP 协议与传输安全；
- 架构依赖约束；
- 从 ArcGIS Pro 现场运行中复现的回归问题。

自动化测试不能替代宿主验证。ArcGIS 特有行为——SDK 线程模型、GP 冷启动、安装包注册与真实地理数据库锁——仍需要在与公共仓库隔离、已获许可的 Pro 工作站上验证。
