# 数据质量批量检查

## 触发条件
- "数据质量"、"质检"、"质量检查"

- "空值"、"重叠"、"拓扑错误"、"坐标系不对"
- "字段缺失"、"数据完整性"

## 执行流程

### 步骤 0：确定检查范围

**目标**：确认要检查哪些图层，用什么标准。

**询问用户**：
- "检查全部图层还是指定图层？"
- "按照什么规范检查？（默认：市级国土空间总体规划数据库规范 2021试行）"
- "是否需要生成质检报告？"

### 步骤 1：完整性检查

**目标**：检查必填字段是否有空值。

**规划数据必填字段参考**（市级国空数据库规范）：

| 字段名 | 含义 | 类型 | 必填 |
|--------|------|------|------|
| YSDM | 要素代码 | TEXT(10) | 是 |
| BSM | 标识码 | TEXT(18) | 是 |
| DLBM | 地类编码 | TEXT(10) | 是 |
| JSMJ | 计算面积 | DOUBLE | 是 |
| TBMJ | 图斑面积 | DOUBLE | 是 |
| QSXZ | 权属性质 | TEXT(20) | 是 |
| TBBH | 图斑编号 | TEXT(20) | 是 |
| XZQDM | 行政区代码 | TEXT(12) | 是 |
| XZQMC | 行政区名称 | TEXT(100) | 是 |

**Agent 操作**：直接使用 `management_SelectLayerByAttribute`，对每个必填字段执行空值查询：
- WHERE 条件：`字段名 IS NULL OR 字段名 = ''`
- 用 `agent_get_selection` 查看选中记录数
- 若 > 0，记录为问题

**常见问题及修复**：

| 问题 | 严重度 | 修复方式 |
|------|--------|---------|
| YSDM 空值 | 严重 | 先查知识库中的 `land-classification-lookup.md`，确认该图层对应的要素代码，再通过 `management_CalculateField` 填入 |
| BSM 空值 | 严重 | 用 `management_CalculateField` 生成递增编号 |
| TBBH 空值 | 一般 | 用行政区代码+顺序号生成 |
| JSMJ 空值 | 严重 | 用 `management_CalculateField` 配合 `!shape.area!` 计算 |
| 要素数为0 | 严重 | 检查数据是否导入成功 |

### 步骤 2：准确性检查

**目标**：检查坐标系、面积字段、字段类型是否正确。

**Agent 操作**：使用 `agent_get_map_info` 查看当前地图坐标系。

**检查项**：

1. 坐标系是否 CGCS2000 系列：
   - 地理坐标系 WKID=4490（大范围、三调）
   - 投影坐标系 3度带（如 4527/4528/4543）
   - 如果不是 CGCS2000 → 使用 `management_Project` 转换

2. 面积字段数据合理性：
   - 直接执行 `management_SelectLayerByAttribute`，WHERE：`面积字段 <= 0 OR 面积字段 IS NULL`
   - 用 `analysis_Statistics` 按地类汇总，检查各地类面积之和约等于总面积
   - 用 `agent_describe_layer` 查看字段类型，确保面积字段为 DOUBLE

3. 字段类型正确性：用 `agent_describe_layer` 查看，代码字段应 TEXT，面积字段应 DOUBLE，日期字段应 DATE

### 步骤 3：一致性检查

**目标**：检查图层间逻辑关系。

**三线互检**（最常出问题）：
- 使用 `analysis_Intersect` 检查生态红线与基本农田是否重叠
- 使用 `analysis_Intersect` 检查生态红线与开发边界是否重叠
- 使用 `analysis_Intersect` 检查基本农田与开发边界是否重叠

**建设用地包含关系**：
- 使用 `analysis_Erase`（建设用地, 开发边界），如有结果则存在开发边界外的建设用地

**行政区代码一致性**：
- 用 `agent_describe_layer` 查看各图层 XZQDM 字段唯一值，确保多图层间代码一致

### 步骤 4：拓扑检查

**目标**：检查几何拓扑错误。

**Agent 操作**：按现有工具完成拓扑检查：
- `three_lines` action — 批量检查三线冲突
- `get_rules <几何类型>` — 获取该类型的拓扑规则列表
- `check_rule <规则ID>` — 详细查看某条规则

**面图层自检**：
- 用 `analysis_Intersect` 对图层自身做相交，如果结果 > 0 则存在重叠
- 用 `analysis_Erase`（边界图层, 目标图层），如有结果则存在空隙

**线图层自检**：
- 用 `analysis_Intersect` 检查自相交
- 用 `analysis_Intersect` 配合相关拓扑工具检查悬挂线和重复线

### 步骤 5：生成质量报告

**目标**：汇总所有问题，生成可提交的质检报告。

**Agent 操作**：将以上各步骤的检查结果汇总，生成自然语言报告。包含：
1. 检查概况（检查时间、检查范围、检查标准）
2. 完整性检查结果（各图层必填字段空值统计）
3. 准确性检查结果（坐标系、面积字段问题）
4. 一致性检查结果（图层间冲突）
5. 拓扑检查建议（需要执行的 GP 工具和预期结果）
6. 问题汇总（按严重程度分级）
7. 修复建议（每类问题的具体修复方法）

## 输出确认清单
- [ ] 完整性：所有必填字段空值率不高于 1%
- [ ] 准确性：坐标系统一为 CGCS2000
- [ ] 准确性：面积字段已计算且为 DOUBLE 类型
- [ ] 一致性：三线无重叠冲突
- [ ] 一致性：建设用地在开发边界内
- [ ] 拓扑：面无内部重叠
- [ ] 拓扑：面无超过 100平方米 的空隙
- [ ] 报告：质检报告已生成并保存

## 痛点与修复速查

### 痛点1：YSDM 字段全空
场景：CAD 导入的数据没有 YSDM 字段或全为空。
快速修复：先查知识库中的 `land-classification-lookup.md` 查询应有的要素代码，再用 `management_CalculateField` 批量填入。

### 痛点2：面积字段是文本类型
场景：Excel 导入的面积字段被识别为 TEXT 类型。
快速修复：用 `management_AddField` 新建 DOUBLE 字段，用 `management_CalculateField` 配合 `float(!原字段!)` 转换。如原字段值有逗号或单位，先清理再转换。

### 痛点3：部分数据偏离主流坐标系
场景：项目中有个别图层是 Xian 1980 或 WGS84 坐标系。
快速修复：用 `management_Project` 转换。Xian 1980→CGCS2000 需要地理变换参数，WGS84→CGCS2000 偏移量极小可直接用 Project。

### 痛点4：图斑面积与属性面积不符
场景：Shape_Area 字段值与 JSMJ 属性值差异大。
处理方式：以椭球面积为基准（`!shape.geodesicArea!`），用 `management_CalculateField` 重新计算。

## 快速检查命令速查

以下命令可帮助快速了解数据状况：

- `/layers` — 列出所有图层
- `/layer <图层名>` — 查看某图层的字段详情
- `/map` — 查看当前地图坐标系
- `/search <关键词>` — 搜索 GP 工具

Agent 会自动选择合适的工具执行上述检查流程，无需手动输入每个命令。
