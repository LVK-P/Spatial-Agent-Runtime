# 数据标准化 Pipeline

## 触发条件
用户提到以下任一关键词或场景：
- "新数据"、"原始数据"、"刚拿到的"、"还没处理"
- 文件扩展名提及 .shp、.dwg、.xlsx、.cad、.dat
- 询问"这个数据能不能用"、"数据格式不对"、"坐标系"
- 导入数据后出现偏移或无法叠加

## 执行流程

### 步骤 1：识别文件格式
**目标**：确定拿到的是什么类型的数据

| 文件格式 | 识别特征 | 标准处理方向 |
|---------|---------|-------------|
| .shp | 文件夹含 .shp/.dbf/.shx 三件套 | 可直接用于 ArcGIS，进入步骤 3 |
| .dwg/.dxf | CAD 文件，可能含多层 | 需要先导入 gdb，进入步骤 2 |
| .xlsx/.xls | Excel 表格，可能是坐标表或属性表 | 判断是坐标表还是纯属性表 |
| .gdb | ESRI 地理数据库 | 可直接用，进入步骤 3 |
| .mdb | 旧版 Access 地理数据库 | 需转换为 .gdb |
| .kml/.kmz | Google Earth 格式 | 需转换为要素类 |
| .json/.geojson | Web 地图格式 | 需转换 |

**需要确认的信息**：
- 数据从哪来的？（测绘院、甲方、网上下载、其他部门）
- 原始数据是什么软件生成的？（CAD、ArcGIS、MapGIS、QGIS）

### 步骤 2：统一格式 → GDB
**目标**：所有数据都转成文件地理数据库(.gdb)中的要素类

```
.shp ──→ "要素类至地理数据库" GP工具 ──→ .gdb\要素类
.dwg ──→ "CAD 至地理数据库" GP工具  ──→ .gdb\要素类（按图层名）
.xlsx ──→ "XY 表转点" 或 "Excel 转表" ──→ .gdb\要素类/表
.mdb ──→ "要素类至地理数据库" 或 手动迁移 ──→ .gdb
```

**常见坑**：
- CAD 文件导入前要先确认图层名不是乱码
- DWG 可能包含几十个图层，只需导入有地理意义的图层
- Excel 如果是坐标表，确认 X/Y 列名和坐标系

### 步骤 3：识别几何类型
**目标**：确认要素是点、线、面，以及是否有 Z/M 值

| 几何类型 | 常见的应用场景 | 特殊处理 |
|---------|--------------|---------|
| 点 (Point) | 地块中心点、采样点、设施位置 | 检查是否有 XY 坐标字段作为备份 |
| 折线 (Polyline) | 道路、河流、界线、等高线 | 检查是否闭合（闭合可做面处理）|
| 面 (Polygon) | 地块、行政边界、用地分类 | 检查拓扑（重叠、缝隙）|
| 多点/多线/多面 | 复合几何 | 拆分或确认是否需要 |

**注意 Z 值和 M 值**：
- Z 值 = 高程，规划中一般不需要，但 3D 分析可能需要
- M 值 = 测量值（如里程），线性参考分析用
- 如果不需要，建议清除：`清除 Z 值` / `清除 M 值` GP 工具

### 步骤 4：坐标系检查与转换
**目标**：所有数据统一到项目坐标系

**常用坐标系对照**（中国大陆规划常用）：
| 坐标系 | WKID | 适用区域 |
|--------|------|---------|
| CGCS2000 3°带 37°N | 4527 | 东经 108°-114°（湖北中西部）|
| CGCS2000 3°带 38°N | 4528 | 东经 114°-120°（湖北东部）|
| CGCS2000 6°带 19°N | 4497 | 东经 108°-114° |
| CGCS2000 6°带 20°N | 4498 | 东经 114°-120° |
| CGCS2000 3°带 37°E | 4542 | 另一个常见变体 |
| CGCS2000 3°带 38°E | 4543 | 湖北东部常用变体 |
| WGS84 地理坐标系 | 4326 | GPS 原始数据 |
| Xian 1980 3°带 37°N | 2362 | 老数据常见 |

**转换流程**：
1. 查看当前要素的坐标系 → 使用"要素属性"或 Python `arcpy.Describe(fc).spatialReference`
2. 与项目基准坐标系比较
3. 如果不一致 → `投影` 工具（不是"定义投影"！）
   - `投影` = 实际改变坐标值
   - `定义投影` = 只改标签不改值（坐标会偏！）

**常见坑**：
- CAD 数据可能没有坐标系信息，需要额外询问
- 不同 CGCS2000 带号之间转换用 `投影`，不是地理变换
- 搞清楚是投影坐标系还是地理坐标系（经纬度 vs 米）

### 步骤 5：字段规范化
**目标**：字段命名和类型符合工作习惯

| 检查项 | 处理方式 |
|--------|---------|
| 字段名是否中文乱码 | 改用英文简写 + 别名设为中文 |
| 字段类型是否正确 | 数字→双精度，代码→文本，日期→日期型 |
| 是否有无用的系统字段 | 删除 Shape_Length/Shape_Area 之外的冗余字段 |
| 关键字段是否有值 | YSDM、DLBM 等代码字段不能为空 |
| 字段名是否符合规范 | 参考项目字段命名标准 |

## 输出确认清单
完成数据标准化后，确认以下项目：

- [ ] 所有数据都在同一个 .gdb 中
- [ ] 所有要素类的坐标系一致
- [ ] 无多余图层（CAD 垃圾层已清理）
- [ ] 关键字段不为空
- [ ] 字段类型正确
- [ ] 数据范围和预期一致（缩放到全图确认）
- [ ] 无 Z/M 值干扰（如不需要）

## 坐标系处理原则

- 明确源坐标系、目标坐标系与适用范围后再执行转换。
- 涉及基准面变化时显式选择与数据区域匹配的地理变换。
- 面积和长度统计前确认采用平面量算还是测地线量算，并记录单位。
- 转换后检查空间范围、控制点偏移和关键要素叠合关系。
